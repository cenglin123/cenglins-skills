# 加密库附件出路：两条互斥路径（2026-10-30 修订）

## 背景（实测修正）

Foxmail 新版的本地邮件文件为**全库加密存储**（7.1.3.52 Storage 布局实测：高熵、无任何
已知魔数），附件明文只能由 Foxmail 自身解密。本工具不破解加密（边界），离线直读
`Mails\<m>` 过不去这一层属预期。

> **旧版本配方已证伪删除**：旧文写「单击选中 = 触发渲染 = 附件解密落缓存」。
> 7.1.3.52 实测：单击/预览只把正文渲染成 `Temp-*\fox(*).html`，**附件不落盘**
> （5 个 Temp 目录、0 个 Attach 子目录、POP3 0 封，四级兜底全空）。不要再按旧配方
> 做「单击触发渲染」的自动化。

渲染缓存的被动收割保留：`extract` 仍会扫 `%APPDATA%\Roaming\Foxmail7\Temp-*`
（含根与一级子目录）——若员工曾在客户端点过「保存附件」，明文可能还在，命中即收割。
但它**不再是可依赖的主动手段**。

## 路径 A（推荐，可批量）：导出 .eml → 语料库模式

1. Foxmail 邮件列表**多选**目标邮件（Ctrl/Shift 可跨页）
2. 右键 →「导出邮件」→ 选 .eml 格式 → 存到目录
3. 之后全 CLI：把 .eml 放进技能目录 `corpus\`（没有就新建），跑默认模式
   `fg.cmd list / show / extract`——附件从 .eml 原位解出，字节数与客户端一致

一次 GUI 批量导出，之后全自动。导出的 .eml 属用户隐私：不外发、不入分发包。

## 路径 B（单封）：右键保存附件

预览区右键附件 →「保存全部附件」/「另存为」。适合一两封的临时需求；
保存到默认位置时，`extract` 的渲染缓存收割也可能直接命中。

## GUI 操作纪律

- 路径 A/B 都只做最小动作集（多选 → 右键 → 导出/保存），不做配方外的窗口操作。
- 导出的 .eml 与保存的附件按邮件隐私同等对待：不外发、不入分发包。
