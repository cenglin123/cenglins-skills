# feedback/ — 运行反馈产出目录

本目录是**下游分发机**向上游回馈运行发现与适配成果的约定位置，
用于 wechat-grep 的长期演进：微信版本升级、环境差异、转写质量、命令行为偏差，
所有在分发机上发现的"SKILL 没预料到的事"，都应有处可去。

## 何时使用（触发条件，满足任一即写）

| 触发 | 典型症状 |
|------|---------|
| **微信版本升级导致特征失效** | `capture_db_key.py` 报"DLL 中未找到内部密钥特征"或全部候选校验失败；`key image` 报模板不匹配 |
| **环境差异导致部署失败** | 数据目录在非常规位置、多账号鉴别失败、权限/会话隔离、杀软拦截形态与 SKILL 描述不符 |
| **转写质量劣化或异常** | 大面积空文本、明显错字模式（可归纳为术语表）、特定 WAV 全部失败 |
| **weflow CLI 行为与 SKILL 描述不符** | 命令参数/输出结构变化、新增/移除能力 |
| **多账号边角** | 档案切换异常、kvcomm 多 code 消歧失败、账号目录命名新形态 |
| **文档缺陷** | SKILL.md 指引走不通、描述与实际行为不符 |

**不要**用 feedback 报告一次性偶然问题（网络抖动、用户误操作）——先按 SKILL 各节
的恢复指引尝试；确认是 SKILL/脚本/环境层面的系统性问题再写。

## 目录约定

每个反馈任务建一个子目录，命名：`YYYYMMDD-<微信版本>-<简述>`，例如：

```
feedback/
└── 20261201-4.1.20.10-DLL特征失效勘察/
    ├── report.md            # 结构化报告（见下模板）
    ├── evidence/            # 脱敏证据：报错原文、命令输出、版本信息
    │   └── ...
    └── fix.diff             # 脚本修正建议（如有，unified diff）
```

## report.md 模板

```markdown
# <一句话标题>

- 日期 / 微信版本 / Windows 版本 / Python 版本：
- 触发命令：
- 现象：（确切报错原文或行为描述）
- 已尝试：（按 SKILL 哪些指引恢复、结果如何）
- 诊断：（你的分析——特征变化？环境差异？参数漂移？）
- 建议：（对 SKILL/脚本的修正方向）

## 证据
（脱敏后的命令输出片段，见硬性要求）
```

## 硬性要求（隐私红线）

- **密钥明文绝不入反馈**：decrypt_key / image_aes_key 只写前 6 位 + `...` + 后 4 位掩码
  或"长度 64 十六进制"这类形态描述
- **wxid 一律占位化**：`wxid_<占位>` 或保留前 8 字符；账号目录名同
- **聊天内容、媒体文件、联系人信息不入反馈**：证据只引用报错、计数、结构、时间戳
- 路径占位化：`<数据根>`、`<账号目录>`、`<微信安装目录>`

## 上游处理

分发者定期收集各分发机的 feedback 子目录：评审诊断与 diff → 合并进
SKILL.md / scripts → 更新版本特征表（如有）→ 归档至 `_archive/feedback/` 留存。
合并后在子目录加 `MERGED.md` 标记（日期 + 处理结论），避免重复收集。
