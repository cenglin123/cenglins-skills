# 方法论篇：这次排障里可迁移的东西

> 下面 8 条与 Win+X 无关——它们是"下次遇到别的 Windows 底层黑箱问题"仍然成立的部分。
> 每条都给了本案例的实证，以及可直接照抄的检查动作。

## 1. 系统文件的版本号会撒谎，哈希不会

`FileVersionInfo` 对 System32 中的文件按路径缓存，同一份内容放在不同路径读出的版本不同。

> 实证：本案例里比对 conhost.exe 版本一度得出"文件已替换成功"的错误结论。

**动作**：比对系统文件一律 `Get-FileHash -Algorithm SHA256`；替换前先存原文件哈希，还原后再比一次。

## 2. 先查清"我自己在哪儿跑"，再动进程

Agent / 脚本的 shell 常常就宿在它准备杀掉的那个进程里。

> 实证：`Stop-Process WindowsTerminal` 会杀掉承载本次会话的 WT，排障中断。

**动作**：动终端/宿主进程前先看父进程链（`Win32_Process.ParentProcessId` 向上走）；
必须重启时用计划任务脱离会话执行。

## 3. oracle 驱动的算法逆向

逆向一个校验算法时，先找**已知正确的样本**当 oracle，实现必须先过 oracle 再上实战。

> 实证：微软自带的 WinX 快捷方式自带合法哈希，是现成 oracle。
> 靠它才发现两处错误：盐值多一个空格、Arguments 读空（8/14 → 14/14）。

**动作**：`winxhash.py verify` 就是这个模式的成品——先自证，再写入。
没有 oracle 就先造一个，别拿生产对象试算法。

## 4. 常量从本机二进制里取，别从文档/开源实现里抄

> 实证：公开 hashlnk 源码的盐是 `links.` 后一个空格，Win10 22H2 twinui.dll 里是两个空格；
> 照抄则全部校验失败，且失败方式是"条目静默消失"，极易误判成别的原因。

**动作**：`winxhash.py salt` 直接扫本机 dll 提取候选常量。凡是"魔法字符串"，都问一句：
这台机器上真是这个值吗？

## 5. 对照实验必须单变量，且每步读回验证

> 实证：多次"实验失败"其实是自身操作 bug——环境变量没导出、两遍 replace 互相污染、
> 假设了并不存在的 `HasLinkInfo`。真正的被测假设根本没被检验到。

**动作**：每个实验步骤结束后立刻读回它自己的产物（TargetParsingPath、存储哈希、LinkFlags、
文件哈希），确认这一步真的生效，再进入下一步。本工具包的 `install.ps1` 把这条写死成了流程：
补丁 → 读回 → 不符就自动换方法。

## 6. 先证伪最小假设，分层隔离

把链路拆成能单独测的层（版本前置 / 注册表意图 / 包注册 / COM 激活 / 扩展目录 / 应用激活 / 端到端），
从最便宜、最不具破坏性的那层开始。

**动作**：见 `troubleshooting.md` 第 2 节表。任何一层能单独给出"成功/失败 + 错误码"，
就比整体"没反应"强一个数量级。

## 7. GUI 兜底不需要用户配合

没有屏幕控制 MCP 时，`keybd_event` 合成按键 + `System.Drawing.CopyFromScreen` 截屏
就足以"亲眼验证"一个菜单的真实行为。

**动作**：`tools\capture-winx.ps1`、`tools\test-winx-key.ps1`。
验证 UI 行为时，测真实入口（菜单）而不是它背后的文件。

## 8. 多因素故障优先怀疑系统深层损伤，及时止损

"每个部件单独测都正常，但整体不通"，且跨补丁、跨账户、跨版本均复现——
这类问题继续点修的期望收益很低。

**动作**：设一个止损线（见 `troubleshooting.md` 第 4 节的五条判据）。
达到就二选一：保留文件的原位修复安装，或改用**绕过方案**（本工具包）。
绕过方案的价值在于它不依赖坏掉的链路被修好。

## 附：最小侵入接管点的一般化

本案例的核心结论其实是一个通用套路：

> 想改变系统 UI 项的行为时，先找到**系统自己用来定位目标的那条间接引用**（这里是
> `ConsoleHostShortcutTarget` 注册表值），改引用指向的对象，而不是改 UI 项本身。

好处：外观、快捷键、提权行为、完整性校验全都由系统原样保留，改动面最小、可还原性最好。
反例是直接改 WinX 目录的 .lnk——要对抗哈希校验，还拿不到 TWINUI 硬编码的显示名与快捷键。

**动作**：面对"UI 项不能改/改了就失效"的场景，先问：系统是通过什么定位这个目标的？
那条链路上有没有一个我能合法改写的中间对象？
