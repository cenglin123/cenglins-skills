# feedback/ — 运行反馈与升级建议产出目录

本目录是**下游分发机**向上游回馈运行发现与升级建议的约定位置，用于
`win-pup-forensics-cleanup` 的长期演进：新案卷暴露的采集盲区、脚本健壮性问题、
文档与真实系统行为的偏差。

## 何时使用（满足任一即写）

| 触发 | 典型症状 |
|------|---------|
| **采集器在真实系统上出错** | 某类证据整体 ERROR（属性缺失、空值调用方法）、进程被安全软件结束导致中断 |
| **溯源能力缺口** | 现有采集项覆盖不到"谁装的"关键证据链（进程创建链、用户活动库） |
| **复核口径缺口** | 已知残留形态（孤儿驱动、被接管的安全中心）未被复核覆盖 |
| **处置流程缺口** | 文档指引在真实场景走不通（如卸载器缺失、共享注册表分支） |
| **文档缺陷** | SKILL.md / references 描述与实际行为不符 |

一次性偶然问题（网络抖动、误操作）不写——先按 SKILL 各节恢复指引尝试。

## 目录约定

每个反馈任务建一个子目录，命名：`YYYYMMDD-<技能版本>-<简述>`，例如：

```
feedback/
└── 20261117-1.0.1-collector-A1-A5/
    └── report.md            # 结构化报告（见下模板）
```

## report.md 模板

```markdown
# <一句话标题>

- 日期 / Windows 版本 / 技能版本：
- 触发依据：（案卷编号或复现条件）
- 现象：（每项一条，给实证）
- 诊断：（根因分析）
- 建议：（对脚本/文档的修正方向，注明是否改动破坏性脚本）
```

## 硬性要求（隐私红线）

- 机名、账号、用户路径一律占位化（`PC-01`、`<用户>`、`<案卷目录>`）。
- 不写具体聊天/文件名中的个人信息；证据只给计数、结构、哈希前缀、时间戳。
- 不附原始证据文件；案卷留在本机案件目录。

## 上游处理

收集 feedback 子目录 → 评审诊断与建议 → 合并进 SKILL.md / scripts → 归档并
在子目录加 `MERGED.md`（日期 + 处理结论），避免重复收集。
