# PUP 识别线索

## 通用线索与判定

以下现象用于生成调查候选，单项不足以定性：
- 多款产品共享签名主体，或同批时间落地。
- OEM/联盟 SDK、Guard/Protect 驱动、私有 Svchost 组。
- 登录任务、更新任务及厂商参数。
- 桌面图标经过跳转器，下载请求和实际落地文件不同。
- 来源数据流缺失、主页配置或扩展权限异常。
- 非自愿清理/优化组件周期调用系统工具，伴随临时文件、日志或其他资源堆积；这类行为可以没有内核保护驱动。按 [性能取证方法](performance-forensics.md) 量化症状并核对实际调用关系。

继续核对用户安装意愿、静默安装日志、下载链、签名有效性、具体配置变更与回装行为。正常安全软件、更新器和合法分发器也可能具有部分特征。禁止按公司名相似、SDK 文件名或单一时间戳断言共同控制或恶意。

## 常见证据来源

- **推装时间线**：查 `%TEMP%` 与下载目录里近期的安装包。`collect-lite-ps2.ps1` 的 `recent-temp-installers` 只扫 `%TEMP%` 第一层的 `*.exe`/`*.tmp`/`*.msi`（默认 180 天内、最多 100 项、不提示截断），只给路径、大小与文件修改时间（`LastWriteTime`），**不含产品名与签名**，需要另读 `(Get-Item).VersionInfo` 与 `Get-AuthenticodeSignature`；zip、子目录与其他用户的 TEMP 需另查。按修改时间排序可重建推装节奏（窗口按案件时间范围调整）；产品名常形如「XX 服务组件」，仅作发现线索，不作匹配或删除依据（`CompanyName` 常为空，来源身份以签名主体为准）。安装包仍在而程序不在，可能是已卸载、未装完，或从未执行，需用 Prefetch、执行痕迹或卸载项区分。
- **弹窗投放**：厂商数据目录下常有 `Pop`、`Wnd`、`Log` 一类子目录与近期图片文件（弹窗素材或截图）；看最近时间并逐张看内容，判断清理前是否仍在投放，记录目录与最近时间作为复查基线。
- **主页/搜索**：核对用户级与机器级（HKCU、HKLM 与 `HKLM\SOFTWARE\Wow6432Node`）的 `Start Page`，同时看渠道号参数；SearchScopes 的采集范围见 SKILL 的降级采集说明。只看用户级会漏掉机器级写入。

## 家族线索的使用方式

具体案例的对象、路径与证据编号见 [案例经过](case-history.md)；案例中的产品名、目录名和渠道号只作为调查线索，不能复制成其他机器的删除正则或默认目标。

| 对象类别 | 需要核对的证据 |
| --- | --- |
| 下载器 / SDK | 下载链、实际落地文件、签名主体、siteid/VendorID 类参数、推广日志 |
| 守护服务 | 精确服务名、宿主进程、ServiceDll、Svchost 组成员、原始 ImagePath |
| 保护驱动 | 原始 ImagePath、签名、运行状态、启动类型、fltmc 挂载情况（fltmc 只列已加载的 minifilter，未列出不代表从未加载；结合服务状态与 `Instances` 子键判断） |
| 跳转快捷方式 | 实际跳转器路径、配置、快捷方式目标；目录名本身不定性 |
| 主页锁定 | 锁主页配置、策略来源、推广框架文件 |
| 安全软件家族 | 区分长期安装、独立推广与后来重装；核对用户保留意愿及与办公软件的共享组件 |

正式处置以本机实际路径、签名、版本和卸载项为准。厂商名相似的目录、源码短片段（misc、_pp 等）和单一时间戳都不能作为批量删除依据。

## 需要避免的因果误读

同一台机器可能同时存在更早的渠道和新的下载渠道；后来下载的正版软件也不能与推广包混为一谈。源码中的短片段、目录名和产品名不适合跨机器批量匹配。厂商关系需独立材料证明；样本共现只支持技术关联。
